# Founder / Product Operating Model

Zugrio should function as a real product-management operating environment, not merely a coding exercise.

## Founder responsibilities

- problem definition and customer discovery;
- product vision and outcome metrics;
- PRDs/RFCs and acceptance criteria;
- backlog priority and release scope;
- explicit risk decisions and non-goals;
- user testing and post-release learning;
- translation between trading, engineering, compliance, security and commercial goals.

## Repository evidence of product work

Maintain `docs/product/` with concise PRDs, user/problem evidence, decision logs, release notes, metrics definitions and experiment results.

GitHub issues/projects should connect product intent to implementation history.

## Technical fluency target

The founder should become capable of explaining and challenging:
- APIs/HTTP;
- relational modeling and SQL;
- authentication/authorization;
- async/concurrency/race conditions;
- idempotency;
- hashes/signatures;
- Git/GitHub;
- testing and CI/CD;
- Docker;
- logging/tracing;
- Zugrio's authority graph.

## CV/portfolio use

Only claim what repository and product evidence support. Do not claim production scale, profitability, regulatory status or validated edge without evidence.
